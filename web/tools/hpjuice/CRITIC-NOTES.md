# HP 타격감 3차 채점 메모 — 다음 3D 세션 인계

세션 결과: **SKIP_3D로 종료** (구현 착수 안 함). 이 파일은 채점 근거만 남긴 것이다.

## 왜 SKIP_3D인가
시작 시 컨테이너 클론이 **원격과 공통 조상이 없는 낡은 8커밋 라인**을 가리켜, 가드가
"최신 3D 마커 15분 전"으로 오판해 작업을 시작했다. 실제 원격에서는 다른 3D 세션이 같은 항목을
이미 2회 채점(3.5 → 4.5/10)까지 진행 중이었고, push 거부 → `pull --rebase` 시 충돌로 드러났다.
재확인 시 8분 전 다른 `[3D작업중]` 클레임이 있어 가드 규칙대로 종료했다.
**가드의 10분 창을 60~120분으로 늘리고, 시작 시 `git fetch`로 원격 tip을 강제 확인할 것** —
같은 원인으로 이 항목이 두 번 중복 구현됐다(987fe5a 인계 메모도 동일 지적).

## B. 이미 main에서 고쳐진 지적 — 착수하지 말 것 (옛 빌드에만 해당)
A의 "가장 치명적 3개" 중 2개가 여기 속한다. 그대로 믿고 재작업하면 헛일이다.
- ❌ **"카메라 반응 0, `hitEnemy`/`killEnemy`에 `shake()` 없음"** → main은 크리에 `shake(0.07)` +
  `fovPunch(0.026, 0.13)`, `killEnemy`에 `hitStop(0.045/0.07)`이 이미 있다.
- ❌ **"임팩트 프레임 무반응, `sin(k*PI)`라 최대 변형이 110ms 뒤"** → main은 넉백을 임팩트
  프레임에 선반영(`m.g.position.x = ox + kb`)하고 `(1-k)²` 복귀 + 부피 보존 스쿼시를 쓴다(프론트로딩).
- ❌ **"크리 외곽선이 1px 55% 알파라 안 보임"** → main은 `.6px rgba(30,10,0,.95)`로 이미 진하다.
- ❌ **"흰 플래시 `emissiveIntensity=1`"** → main은 크리 0.28로 캡했다(단, 아래 C-1 참조).

## C. 재캡처 후 재확인 필요 (그림 근거, 현재 main으로 다시 찍어야 함)
1. **임팩트 프레임이 형태 없는 흰 덩어리** (B의 1순위). `flashMesh`를 0.28로 낮춰 아낀 밝기를
   `impactFlare(0.95)`+`(1.25)` additive가 다시 태워, 히트스톱으로 정지시킨 프레임에 스쿼시·롤·넉백·
   파편이 전부 묻힌다는 지적. 제안: 플레어 크기 0.5/0.62·수명 0.08/0.1로 축소, flareTex를 방사
   글로우 → 초승달+예각 스파이크 마스크로. **A·B가 표현은 달라도 같은 곳을 1순위로 꼽았다.**
2. **처치 버스트의 파편/2색 심지가 흰색으로 클리핑돼 개체·색 구분이 안 됨** — 처치 순간 주변
   40ms 감광으로 절대 밝기가 아니라 **대비**로 터지게 할 것. 파편에 속도 방향 스트레치 추가.
3. **영웅 머리 위 2단 바가 D 스트립 18프레임 전체에 없음** — json은 heroFg 0.42/heroGhost 1.0인데
   화면에 없다. **크롭 버그인지 렌더 문제인지 먼저 규명**할 것(내 하네스의 D 크롭이 풀 뷰포트라
   바 확대 좌표가 어긋났을 가능성이 있다).
4. 앞바 자체 모션 0(컨테이너 펀치 없음), 민트/주황 seam 무장식, 흰 플래시가 앞바 **전체**를
   110~140ms 덮어 잔량·등급색 판독 불가(연타 중엔 재점화로 계속 흼), 바 마감이 플랫(캡슐·그라디언트·
   리딩 엣지 없음), 데미지 숫자가 340ms 동안 opacity 1로 정지 체류.

## D. ⚠️ 하네스 한계 — 다음 채점 전에 반드시 고칠 것

(참고: main에는 다른 세션이 만든 `tools/shot-hitfx.js`(서브스텝 촬영)·`tools/test-hitfx.js`(회귀 15항목)가

## E. 이 브랜치(`3d/hpbar-bloom-overlay`)에 든 것
현재 main에 **머지되지 않은** 실험 1건: HP바를 블룸 패스에서 제외하고 포스트 합성 뒤 오버레이로
얹는 방식(`BAR_LAYER` + `renderBarOverlay`). main의 접근(채움색을 블룸 임계 아래로 + 어두운 배경판
+ `toneMapped:false`)과 목적이 같아 **대부분 중복**이지만, main 방식은 **옆 스파크의 블룸 번짐**까지는
막지 못한다(블룸은 스크린 스페이스 블러라 바 자신의 색과 무관하게 이웃 밝기가 번진다).
위 C-1(플레어 축소)을 먼저 적용한 뒤에도 바가 씻긴다면 검토할 가치가 있다. 그 전에는 채택하지 말 것.
