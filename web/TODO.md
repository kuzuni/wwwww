# 포지마스터 클론 — 남은 작업 목록

작업 규칙: 한 세션(런)에 **하나의 작업만** 진행한다. 완료하면 체크박스를 채우고 커밋·푸시한다.
시작 전 반드시 `git pull --rebase origin main` 으로 최신화한다.

## 제약 (절대 어기지 말 것)
- three.js r128, 클래식 `<script>` 태그 방식 (모듈/빌드 없음)
- `file://` 더블클릭 실행이 항상 동작해야 함 — 외부 CDN·fetch 금지, 에셋은 base64 임베드
- 밸런스 수치는 `web/BALANCE.md`와 `web/data/raw/` 실측치 기준
- 변경한 js는 `node --check`로 문법 검증, GLB 추가 시 `node web/tools/gen-models-data.js`로 재생성
- 디버그 훅: `?tab=`, `?debug=craft|gear|pets|dungeon|tech|mount|ascend`, `?enemy=slime|golem|goblin|bat|mushroom|wolf|imp`

- [x] **대장간 레벨 확률 정보 팝업을 연 채로 업그레이드가 완료돼도 팝업이 갱신되지 않아, "업그레이드 중" 레이아웃(구 시대 확률표·진행바·스킵 버튼)이 그대로 남고 스킵을 누르면 젬이 충분해도 "젬이 부족합니다"로 잘못 표시됨**: `Forge.tickUpgrade()`(forge.js:199-207, 1초 틱마다 호출)는 완료 시 `S.forgeUpgradeEndsAt = null`·레벨 증가·토스트·`UI.renderEquipSheet()`만 호출하고 `UI.renderForgeInfo()`는 호출하지 않는다. `renderForgeLevelView()`(ui.js:271-311 부근)는 `upgrading = !!S.forgeUpgradeEndsAt`로 전체 레이아웃을 분기하므로, 업그레이드 중 이 팝업을 열어둔 채 타이머가 0에 도달하면 새 레벨의 확률표로 전환되지 않고 이전 레이아웃(진행바+"💎 N 스킵" 버튼)이 그대로 남는다. 이 상태에서 "스킵"을 누르면 `Forge.gemSkip()`이 `S.forgeUpgradeEndsAt`가 이미 `null`이라 무조건 `false`를 반환해(forge.js:190-197) `onGemSkipForge()`(26차에서 실패 토스트를 추가한 바로 그 핸들러)가 "💎 젬이 부족합니다"를 띄우는데, 실제 원인은 젬 부족이 아니라 스킵할 업그레이드가 이미 끝나서 없는 것 — 28차에서 고친 기술 트리 노드 팝업과 정확히 동일한 성격의 버그가 형제 팝업인 대장간 확률 정보 팝업에는 남아있었음. 수정: `Forge.tickUpgrade()`의 완료 분기 끝에 28차와 동일한 패턴으로 `if (!UI.els.forgeInfoModal.classList.contains('hidden')) UI.renderForgeInfo();` 추가.
  - 진행 메모: `tickUpgrade()` 완료 분기 끝에 `if (!UI.els.forgeInfoModal.classList.contains('hidden')) UI.renderForgeInfo();` 추가. `renderForgeInfo()`는 `_forgeView`에 따라 레벨/목록/상세 뷰로 자체 분기하므로 어떤 뷰가 열려 있어도 안전하게 최신 상태로 재렌더됨. Node로 시뮬레이션: 업그레이드 완료 시 `renderForgeInfo` 호출·`S.forgeUpgradeEndsAt`이 `null`로 정리된 뒤 호출됨을 확인, `node --check` 통과.
