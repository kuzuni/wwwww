# AAA 폴리싱 루프 기준서 (기능 TODO 소진 후 자동 진입)

목표: web/ 게임의 비주얼·연출 퀄리티를 최신 AAA 모바일 게임 수준으로. "괜찮은데?"는 실패. 비평가가 감탄해야 통과.

**⚠️ 기준 구분 (중요)**:
- **UI 배치**만 원본 포지마스터 스크린샷(web/ref/screens)을 따른다 — 레이아웃 충실도 기준.
- **그래픽 퀄리티는 원본과 비교하지 마라.** 원본은 단순 플랫 카툰이고, 이 클론의 그래픽 목표는 그것을 **한참 뛰어넘는** 것이다. 기준은 절대 기준: "이 스크린샷을 최신 AAA 모바일 3D 게임(예: 최고 수준의 방치형/캐주얼 3D 게임)의 스토어 스크린샷이라고 해도 믿을 수 있는가?" 비평가는 각 영역을 10점 만점으로 채점하고 **9점 이상만 통과**. 원본보다 좋은 건 당연한 전제이지 합격 사유가 아니다.

## 영역 6개 (한 번에 하나씩, 각 영역이 통과할 때까지 반복)
1. **지형/배경** — 지형 셰이딩, 하늘 그라데이션, 안개 깊이감, 원경 실루엣, 챕터별 분위기 차별화
2. **라이팅/포스트** — 림라이트, 블룸 느낌(셰이더 근사), 그림자 품질, 챕터별 색보정
3. **전투 이펙트** — 타격감(히트스톱·플래시), 파티클, 무기 트레일, 카메라 쉐이크 완급, 처치 연출
4. **캐릭터/몬스터** — 모션 보간, 스쿼시&스트레치, 등장/사망 연출, 대기 모션 생동감
5. **UI/HUD** — 마이크로 인터랙션(버튼 눌림·팝업 스프링), 전환 애니메이션, 타이포·아이콘 일관성, 숫자 카운트업
6. **사운드** — 타격/보상/UI 사운드 타격감, 레이어링, 음량 밸런스

## 루프 프로토콜 (영역당)
1. 개선 구현 (아래 기술 제약 준수)
2. **혹독한 비평가 검증**: Playwright로 해당 영역이 드러나는 실제 스크린샷 3장 이상 촬영.
   서브에이전트(Task)를 쓸 수 있으면 비평가를 별도 에이전트로 분리하고, 없으면 스스로 역할을 바꿔 최대한 가혹하게 평가.
   - 영역 ①~④·⑥ (그래픽/연출/사운드): **AAA 절대 기준 10점 채점** — "최신 AAA 모바일 3D 게임 스크린샷이라고 믿을 수 있는가?" 9점 미만이면 실패. 구체적 결함 목록(라이팅·색·밀도·타이밍·디테일)을 남길 것.
   - 영역 ⑤ (UI/HUD): 배치는 원본 스크린샷과 블라인드 비교(레이아웃 충실도) + 마감 퀄리티는 AAA 10점 채점 병행.
3. 통과 기준 충족 시 → 커밋·푸시 → 다음 영역. 실패면 결함 목록 기반으로 1번 반복.
4. 영역당 한 세션에서 3회 반복해도 통과 못 하면, 결함 목록을 이 파일 하단 '진행 로그'에 기록하고 커밋 — 다음 세션이 이어받는다.

## 기술 제약 (절대)
- three.js r128 클래식 스크립트, file:// 실행, 외부 CDN·에셋 파일·웹폰트 금지
- 텍스처는 전부 절차적 생성(캔버스/셰이더), 커스텀 ShaderMaterial 적극 사용
- 파티클·소품은 인스턴싱(InstancedMesh)으로 성능 확보
- 모바일 세로 9:16, 중급 폰 기준 60fps 유지 — 이펙트 추가 후 반드시 프레임 확인
- **게임 로직·밸런스·저장 데이터는 건드리지 않는다.** 보이는 것/들리는 것/느껴지는 것만.
